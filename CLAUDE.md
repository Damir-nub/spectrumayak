Этот документ - карта проекта. Читай его в начале каждой сессии, чтобы понимать, где что лежит и как с этим работать.

## Что это за проект

**СпектраМаяк** - веб-приложение (Web App) для автоматизации диагностики РАС у детей с **конкретными индивидуальными рекомендациями**. Помогает дефектологам, логопедам, психологам и **родителям** не только рассчитать результаты, но и получить **детальный план действий**: что делать, если ребёнок кричит, не спит, не ест, не реагирует на имя, и другие конкретные ситуации.

Генерирует **индивидуальные пошаговые инструкции** для каждого ребёнка на основе профиля по 5 модулям (коммуникация, речь, игра, стереотипии, адаптация). Подробности - в [`.business/INDEX.md`](.business/INDEX.md).

**Ключевое решение (2026-04-26):** Web App вместо Local/Electron — проще разработать за 3-6 месяцев, легче монетизировать онлайн-подпиской. Разработка ведётся с помощью ИИ-агента Claude Code.

## Ключевые принципы проекта

1. **Точность** — только валидные, научно обоснованные методики с подтверждёнными авторскими правами (оригинальная система вдохновлённая ADOS-2, не копия)
2. **Удобство** — минимум ручной работы, максимум автоматизации, интерфейс как бумажные формы
3. **Доступность** — работает как Web App (требует интернет), но с минимизацией данных (без ФИО, только ID)
4. **Полнота** — охват всех аспектов диагностики РАС в единой системе (5 модулей: коммуникация, речь, игра, стереотипии, адаптация)
5. **Конкретные рекомендации** — НЕ "обратитесь к специалисту", а ПОШАГОВЫЕ ИНСТРУКЦИИ: что делать, если кричит / не спит / не ест / не реагирует на имя / бьётся головой / плохо адаптируется к изменениям. Индивидуально для каждого ребёнка на основе профиля по модулям.

## Стек и разработка

**Разработка:** Весь код пишется с помощью ИИ-агента Claude Code. Это заменяет команду разработчиков и позволяет создавать продукт быстро и качественно.

**Frontend:** Next.js 14 (App Router), React 18+, TypeScript, Tailwind CSS, shadcn/ui (компоненты)

**Backend:** Next.js API Routes, PostgreSQL (БД), Prisma (ORM)

**Схема БД (Prisma):**

- users (id, email, password, subscription_tier, created_at)
- children (id, user_id, code, age_months, gender)
- assessments (id, child_id, date, module_1_score, module_2_score, module_3_score, module_4_score, module_5_score)
- reports (id, assessment_id, pdf_url, created_at)

**API эндпоинты:**

- POST /api/auth/register, /api/auth/login
- GET/POST /api/children, GET /api/children/[id]
- POST /api/assessments, GET /api/assessments/[id]
- GET /api/reports/[id], POST /api/reports/[id]/generate-pdf

**Auth:** NextAuth.js (email/password)

**Hosting:** Локально (localhost:3000) для разработки, Vercel или российский хостинг (Selectel, Timeweb) для продакшена

## Как работать с проектом

- Перед любой задачей - прочитай этот файл, затем нужные документы из [`.business/`](.business/) и [`plans/`](plans/).
- Если меняется бизнес-логика - обнови [`.business/INDEX.md`](.business/INDEX.md) и нужные файлы.
- Если меняется технический план - обнови соответствующий план в [`plans/`](plans/).
- Если появляется новая важная папка или документ - обнови этот `CLAUDE.md`.

## ВАЖНО: план для каждой новой функции

Любая функция, которую мы создаём в любом чате, всегда оформляется планом в папке [`plans/`](plans/).

Правила:

1. Один план = одна функция. Если план уже есть - работаем с ним.
2. Имя файла: `YYYY-MM-DD-название-функции.md`.
3. План делится на фазы. У каждой фазы статус `[ ]` или `[x]`.
4. В конце плана - итоговый блок: реализован целиком или нет, что осталось.
5. Любой агент обязан актуализировать план после каждой сессии.

## ВАЖНО: завершение каждого чата

В конце каждой сессии записывай рефлексию в файл [`.business/история/YYYY-MM-DD-краткое-название.md`](.business/история/) (создавай папку при необходимости).

Формат:

1. Какая задача была поставлена.
2. Как я её решал.
3. Решил ли - да / нет / частично.
4. Эффективно ли решение, что можно было лучше.
5. Как было и как стало.
